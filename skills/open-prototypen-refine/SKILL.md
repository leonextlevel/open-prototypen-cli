# Refine

Read the audit and affected product/design artifacts. Decide which findings to fix or accept explicitly, with reasons. Use the design skill's references, such as [intentional design](../open-prototypen-design/references/intentional-design.md) and [the design system reference](../open-prototypen-design/references/design-system.md), for the decision behind each fix, and check each fixed screen again with [the design review questions](../open-prototypen-design/references/review.md) so a fix does not break consistency with other screens. Edit the relevant Markdown, `design/system.yaml`, and OpenPencil nodes deliberately rather than regenerating everything. When a change adds a token or reusable component, update the contract, run `open-prototypen system apply`, and update the samples and native component masters on the `Design System` page before changing linked screen instances. When a change removes or renames a token, rebind its nodes and run `open-prototypen system apply --prune`; it refuses variables still bound to nodes. Keep the page's component states aligned with the inventory. Recheck SVG vectors and represented states. When you replace a screen frame or action node, give the new node the old reference with `open-prototypen ref set`, and update the text labels of changed token samples; `validate canvas` warns `token-label` about labels that still show an old value. When the app has the project's `.fig` open through MCP, follow the save-and-reopen hand-off in [the OpenPencil MCP reference](../open-prototypen-design/references/openpencil-mcp.md). Render, inspect, run `validate canvas --json`, and rebuild the navigable prototype after changes. Record each finding's decision, fixed or accepted, in the audit's `Resolution` table with the evidence that the rebuilt prototype resolves it, and keep unresolved critical findings visible. Update `Summary` and other statements in the report that no longer hold. Ask a separate agent context to re-check critical and high findings in the rebuilt prototype and fill "Verified by"; do not mark your own fixes as verified. `open-prototypen status` warns `audit-stale` while the audit report is older than the `.fig`, `system.yaml`, or `interactions.yaml`; resolve it by re-checking the changed prototype and updating the report, not by touching the file.
